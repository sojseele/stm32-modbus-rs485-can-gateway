# C8T6 电机版与 ZET6 网关版接线说明

本文按照当前工程代码和已经使用的硬件整理。两块板的角色不同：

| 板子 | 工程 | 作用 |
|---|---|---|
| ZET6 | 网关工程 | 网关：PC 的 Modbus/RS485 ↔ CAN |
| C8T6 | 电机节点工程 | 电机节点：CAN 接收控制、控制电机/LED、返回状态 |

### 网关版 ZET6 的板载收发器

根据开发板参数表，ZET6 已经集成以下接口芯片：

| 接口 | 板载芯片 | 终端电阻 |
|---|---|---|
| CAN | TJA1042T/3 | 带 120 Ω 终端电阻 |
| RS485 | MAX485 | 带 120 Ω 终端电阻 |

因此，ZET6 网关侧不需要另外接 SN65 或 MAX485 模块。ZET6 的 MCU 引脚已经在板内连接到对应收发器，实际接线时使用开发板上的 CANH/CANL、485A/485B 端子。

## 一、最重要的 CAN 总线接线

CAN 总线必须经过 CAN 收发器，**不能把 MCU 的 CAN_TX/CAN_RX 直接接到对方的 CANH/CANL**。本项目中，ZET6 使用板载 TJA1042T/3，C8T6 使用外接 SN65（或同类 CAN 收发器）。

### 1. ZET6 网关版 MCU 侧

当前网关代码使用 CAN1 重映射。ZET6 底板已经把 PB8/PB9 接到板载 TJA1042T/3，因此不需要再从 PB8/PB9 飞线到外部 SN65：

```text
ZET6 PB9  (CAN1_TX) -> 板载 TJA1042T/3（板内连接）
ZET6 PB8  (CAN1_RX) <- 板载 TJA1042T/3（板内连接）
ZET6 CANH            -> CAN 总线 CANH
ZET6 CANL            -> CAN 总线 CANL
```

ZET6 的 CAN 接口有两个端子，均由板载 CAN 电路引出。实际使用哪一个端子应以开发板丝印和终端电阻位置为准，不要把两个端子当作两个独立 CAN 控制器。

### 2. C8T6 电机版 MCU 侧

当前 C8T6 代码使用 CAN1 默认引脚：

```text
C8T6 PA12 (CAN1_TX) -> C8T6 侧 SN65 的 TXD
C8T6 PA11 (CAN1_RX) <- C8T6 侧 SN65 的 RXD
C8T6 3.3V            -> SN65 VCC（以收发器型号要求为准）
C8T6 GND             -> SN65 GND
```

注意 TXD/RXD 的连接是“同名连接”，不是交叉连接：

```text
MCU CAN_TX -> 收发器 TXD
MCU CAN_RX <- 收发器 RXD
```

### 3. ZET6 与 C8T6 的 CAN 总线侧

```text
ZET6 板载 TJA1042T/3 CANH <-> C8T6 侧 SN65 CANH
ZET6 板载 TJA1042T/3 CANL <-> C8T6 侧 SN65 CANL
ZET6 GND                   <-> C8T6 GND
```

CANH 和 CANL 不能接反。建议把两块板的 GND 也连接起来，尤其是使用独立 USB 供电时。

总线两端需要终端电阻。ZET6 板载 CAN 接口带 120 Ω 终端电阻，C8T6 侧 SN65 模块如果也带 120 Ω 电阻，应让这两个电阻分别位于总线两端；中间节点不要再并联终端电阻。若 SN65 模块的终端电阻可通过跳帽选择，应根据它是否位于总线末端决定是否安装。没有终端电阻或终端过多，都可能造成 CAN 接收中断异常或发送邮箱长期忙。

SN65 的 `STB`、`EN`、`RS` 等待机/使能引脚必须处于正常收发状态，不能悬空或保持待机电平。不同模块的引脚名称可能不同，接线前以模块丝印和数据手册为准。

## 二、PC 与 ZET6 网关版的 RS485 接线

ZET6 已经板载 MAX485。当前网关工程的 RS485 使用 USART2，并由 PC2 控制收发方向；USART2 与 MAX485 的连接已经在开发板内部完成：

```text
ZET6 PA2 (USART2_TX) -> 板载 MAX485 DI（板内连接）
ZET6 PA3 (USART2_RX) <- 板载 MAX485 RO（板内连接）
ZET6 PC2             -> 板载 MAX485 DE 和 /RE（板内连接）
```

使用 ZET6 开发板上集成的 MAX485 时，只使用板上的 `485A`、`485B` 端子，不要再把 USB 转换器接到 MCU 的 USART2 引脚上，也不需要另接一个 MAX485 模块。

你使用的是照片中的 USB-RS485 转换器，外壳标识为 `USB RS485`、`CH340/34`、`RS232-USB-RS485 V4.0`，端子标识为 `485A`、`485B`、`GND`、`GND`、`5V`。它用于 PC 与 ZET6 网关之间的 Modbus RTU/RS485 通信，不是 ST-LINK：

```text
USB-RS485 转换器 485A <-> ZET6 485A
USB-RS485 转换器 485B <-> ZET6 485B
USB-RS485 转换器 GND  <-> ZET6 GND（建议连接）
USB-RS485 转换器 USB  <-> PC
```

转换器上的两个 `GND` 通常是并联引出的地端，使用其中一个即可。`5V` 端子通常是 USB 侧的 5 V 电源引出端，不能接到 ZET6 的 3.3 V 电源脚，也不要在未确认模块电源方向前用它给开发板供电。正常测试时只通过 USB 给转换器供电，RS485 通信只接 `485A`、`485B`，并按需要连接 GND。

若转换器标记为 `A/B` 或 `D+/D-`，优先按设备标识连接；如果收发完全没有反应，可在断电后交换 A/B 进行确认，但不能把 RS485 A/B 接到 CANH/CANL。

当前网关代码中：

```text
USART2 PA2/PA3：Modbus RS485 数据
PC2：RS485 收发方向
USART1 PA9/PA10：printf 调试串口
```

ZET6 开发板自带 CH340，可用于查看网关版 USART1 的 `printf` 日志。它与板上的 MAX485、以及外接的 USB-RS485 转换器是三套不同功能：

```text
ZET6 板载 CH340       -> 电脑：查看网关版 printf
ZET6 板载 MAX485      -> 485A/485B：Modbus RS485 通信
外接 USB-RS485 转换器 -> 电脑：连接 Modbus Poll
```

## 三、C8T6 电机版的 ST-LINK 调试接线

C8T6 使用 ST-LINK/V2 进行程序下载和 Keil Debug。ST-LINK 连接的是 SWD 调试接口，不是 USART 串口，也不会把 C8T6 的 `printf` 自动显示到串口调试助手：

```text
ST-LINK SWDIO -> C8T6 SWDIO
ST-LINK SWCLK -> C8T6 SWCLK
ST-LINK GND   -> C8T6 GND
ST-LINK NRST  -> C8T6 NRST（建议连接）
ST-LINK 3.3V  -> C8T6 3.3V（可选，避免两路电源冲突）
```

如果还需要查看 C8T6 的 `printf` 日志，需要另接你现在使用的 USB-TTL 串口转换器（不能把照片中的 USB-RS485 转换器直接接到 USART1）：

```text
C8T6 PA9  (USART1_TX) -> USB-TTL 转换器 RXD
C8T6 PA10 (USART1_RX) <- USB-TTL 转换器 TXD（只看日志时可不接）
C8T6 GND              -> USB-TTL 转换器 GND
```

串口助手参数：`115200 baud, 8 data bits, no parity, 1 stop bit`。C8T6 的 USB-TTL 只用于查看电机版日志；照片中的 USB-RS485 转换器留给网关版的 RS485/Modbus 通信，不能直接当作 C8T6 的普通 USB-TTL 调试串口使用。

如果只进行 ST-LINK 下载和 Debug，C8T6 最少连接：

```text
ST-LINK SWDIO -> C8T6 SWDIO
ST-LINK SWCLK -> C8T6 SWCLK
ST-LINK GND   -> C8T6 GND
```

注意：ST-LINK 的 SWDIO、SWCLK 不能接到 PA9/PA10；PA9/PA10 是 USART1 调试串口，只在使用 USB-TTL 转换器查看日志时连接。

## 四、ST-LINK/V2 接线

ST-LINK 用于下载程序和 Keil Debug，不是 USART 数据线，也不会自动把串口日志传到电脑。

### C8T6 SWD

```text
ST-LINK SWDIO -> C8T6 SWDIO
ST-LINK SWCLK -> C8T6 SWCLK
ST-LINK GND   -> C8T6 GND
ST-LINK 3.3V  -> C8T6 3.3V（可选，避免两路电源冲突）
ST-LINK NRST  -> C8T6 NRST（建议连接）
```

### ZET6 SWD

```text
ST-LINK SWDIO -> ZET6 SWDIO
ST-LINK SWCLK -> ZET6 SWCLK
ST-LINK GND   -> ZET6 GND
ST-LINK 3.3V  -> ZET6 3.3V（可选，避免两路电源冲突）
ST-LINK NRST  -> ZET6 NRST（建议连接）
```

一次只连接一个目标板进行下载和 Debug，避免两个板的 SWD 信号线混在一起。

## 五、两块板同时工作时的整体连接图

```text
                         PC
                          |
                USB-RS485 转换器
                    A/B/GND
                          |
                 ZET6 网关版 RS485
             PA2/PA3 + PC2 方向控制
                          |
                  ZET6 CAN 收发器
                    CANH/CANL
                       ||
                    CAN 总线
                       ||
                C8T6 CAN 收发器
                    CANH/CANL
                          |
                PA11/PA12 CAN1
                          |
                    C8T6 电机版
                          |
                    ST-LINK/V2
                 SWDIO/SWCLK/GND
                 （下载和 Keil Debug）
```

说明：C8T6 的 `PA9/PA10 USART1` 连接外接 USB-TTL 以查看电机版日志；ZET6 网关版日志使用开发板自带 CH340。照片中的 USB-RS485 转换器专门连接 ZET6 的 RS485，不能接到 C8T6 的 PA9/PA10。

## 六、上电前检查清单

1. ZET6 的 CAN 引脚是 `PB8/PB9`，由板载 `TJA1042T/3` 引出 CANH/CANL，不是 `PA11/PA12`。
2. C8T6 的 CAN 引脚是 `PA11/PA12`。
3. C8T6 的 MCU `CAN_TX/CAN_RX` 接 C8T6 侧 SN65 的 `TXD/RXD`；ZET6 直接使用板载 TJA1042T/3 的 CANH/CANL 端子。
4. CANH 对 CANH，CANL 对 CANL，不能交叉。
5. 两块板、两个收发器和必要的 USB 转换器共地。
6. C8T6 侧 SN65 的供电电压、待机/使能脚和终端电阻配置正确；ZET6 侧使用板载 TJA1042T/3。
7. ZET6 的 RS485 使用板载 MAX485，外接照片中的 USB-RS485 转换器；ZET6 引脚为 `PA2/PA3/PC2`。
8. C8T6 使用 ST-LINK 连接 SWDIO、SWCLK、GND 进行下载和 Debug；ST-LINK 不是 USART 转换器。
9. Modbus Poll 使用照片中的 USB-RS485 转换器，不使用 ST-LINK 代替 RS485；C8T6 日志使用外接 USB-TTL，ZET6 日志使用板载 CH340。
10. 下载或 Debug 时不要让另一块板长期停在断点，否则可能影响 CAN ACK 和状态机时序。

## 七、当前工程对应的通信参数

```text
CAN：500 kbit/s，CAN1，标准帧
网关 -> 电机控制 ID：0x101，DLC=8
电机 -> 网关状态 ID：0x201，DLC=8
ZET6 调试 printf：USART1，PA9/PA10，115200 8N1
ZET6 Modbus RS485：USART2，PA2/PA3，PC2 方向控制
C8T6 调试 printf：USART1，PA9/PA10，115200 8N1
```
